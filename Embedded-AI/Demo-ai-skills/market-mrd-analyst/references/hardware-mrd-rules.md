# 硬件/消费电子 MRD 规则

当产品包含实体硬件、电子设备、传感器、无线通信、电池、外壳、配件、套装、模组、整机、耗材、IoT、可穿戴、音频/视频设备、仪器设备时，除通用 MRD 规则外必须应用本文件。

## 1. 先确认产品边界

硬件产品边界不清时，不能继续写完整 MRD。必须让用户确认：

- 形态：整机 / 模组 / 配件 / 套装 / 软件+硬件服务 / 其他。
- 包含物：主机、发射端、接收端、传感器、充电盒、电池、线材、App、云服务、耗材、包装。
- 不包含物：明确排除哪些组件、服务和场景。
- 首版场景：只选 1 个起步场景；其他场景列为后续扩展。

如果用户只给了模糊名词（如"收音器"、"检测仪"、"手环"、"摄像头"、"传感器"），先问边界；不要替用户把模块扩展成整机或套装。

## 2. 强制选择 Beachhead 起步人群

目标用户超过 2 类时，必须让用户选 1 个起步人群。MRD 可以记录其他人群，但不能把多个购买逻辑混在一个首版判断里。

输出格式：

| 人群 | 使用场景 | 购买理由 | 预算/决策方式 | 获客渠道 | 是否作为首版 |
|---|---|---|---|---|---|

购买者、使用者、影响者不同的时候必须拆开写。

## 3. 市场规模口径

不得把上位市场直接写成 TAM，除非口径与目标产品一致。市场规模必须拆成：

- 上位参考市场：相邻或更宽口径，只用于说明背景。
- 目标 TAM：与目标产品/地区/人群/场景匹配的理论市场；无数据就写无结论。
- SAM：首版可服务市场；必须扣除地区、场景、渠道、产品边界。
- SOM：团队在 1-3 年可获得市场；必须有渠道、预算、产能、转化或销售能力证据。

如果只有上位市场数据，表格里不得把该数字放进 TAM 行；写为"上位参考市场"，并把目标 TAM/SAM/SOM 标为无结论。

## 4. 硬件竞品必须覆盖电商现实

硬件竞品不能只查官网。直接竞品应尽量覆盖：

- 官网功能/规格。
- 京东/天猫/抖音/淘宝/拼多多/亚马逊等实际售价或价格带。
- 销量/评价数/榜单/热卖信号（如果可查）。
- 差评和用户痛点主题。
- 退货、售后、耐用性、兼容性、耗材/配件成本线索。

没有查到电商或评论数据时，必须在竞品文件和 MRD 中写"电商现实缺口"，不能用官网功能替代真实渠道反馈。

## 5. 差异化必须变成可测命题

差异化不能只写口号。必须写成：

| 差异化命题 | 对比对象 | 测试条件 | 指标 | 通过阈值 | 证据状态 |
|---|---|---|---|---|---|

阈值来源优先级：

1. 用户提供的业务目标或历史数据。
2. 已查证的行业/竞品公开标准。
3. 用户确认的测试门槛。
4. 如果都没有，写"需用户确认阈值"，不要编数字。

## 6. 技术可行性不能只看"能不能做"

硬件技术评分必须考虑团队能力。缺少以下任一关键能力且没有方案商/供应链证据时，技术可行性默认不得高于 3/5；若产品依赖无线、音频/图像算法、医疗/安全、精密测量、量产一致性且团队能力未知，默认不得高于 2/5。

必须检查：

- 核心器件和供应链成熟度。
- 固件/算法/射频/结构/工业设计/测试能力。
- 量产良率、一致性、校准、老化、可靠性。
- 认证、安规、EMC、无线、电池、环保。
- 维修、退换货、售后和质保成本。
- App/云服务/账号/数据安全依赖。

## 7. 合规与认证拆解

硬件合规不能只写"需认证"。按适用性拆：

| 类别 | 可能事项 | 当前判断 | 需要谁复核 |
|---|---|---|---|
| 无线 | SRRC/型号核准/微功率设备/频段功率限制 |  | 认证机构 |
| 电磁兼容 | EMC/EMI |  | 实验室 |
| 安规/质量 | CCC/GB 标准/平台质检 |  | 认证机构 |
| 电池 | UN38.3/MSDS/运输/充电安全 |  | 电池供应商/物流 |
| 环保 | RoHS/REACH/包装标识 |  | 认证机构 |
| 数据 | App 隐私/录音/位置/账号/云同步 |  | 法务/合规 |
| 平台 | 电商准入/类目资质/售后规则 |  | 渠道方 |
| 出口 | CE/FCC/UKCA/地区无线认证 |  | 认证机构 |

无法判断时写"需专业复核"，不要写成已满足。

## 8. 验证计划必须有决策阈值

验证计划必须包含：

- 继续投入阈值。
- 调整方向阈值。
- 暂停/放弃阈值。
- 样本量或最小测试规模。
- 单位经济底线：目标毛利、最大 CAC、退货率、故障率、售后成本。无证据时写"需用户确认"。

不得只写"获得反馈""找到痛点""获取订金"。每个验证项都必须说明如何决定 Go / Pivot / Stop。

## 9. 硬件 MRD 最低完整度检查

最终输出前自检：

- 产品边界是否明确到整机/模组/配件/套装。
- 首版起步人群是否唯一。
- 上位市场是否与目标 TAM 分开。
- 竞品是否包含官网 + 电商/评论/价格现实，或明确缺口。
- 差异化是否可测试。
- 技术评分是否考虑团队能力和量产。
- 合规是否拆到无线、电池、EMC、平台等类别。
- 验证计划是否有决策阈值。

任一项缺失，必须在 MRD 顶部"暂无结论的关键缺口"中列出，并在 process-log 记录。
