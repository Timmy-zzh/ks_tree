# MRD 写作指南

## 写作原则

- 先结论，后证据。
- 每段服务于决策，不写空泛宣传。
- 区分事实、推断和假设（用来源标签）。
- 用表格承载对比，用清单承载风险，用短段落解释逻辑。
- 结尾必须给出可执行下一步。

## 质量门槛

写 full-mrd 时，不能只把模板填满。输出前必须检查：

- 产品边界是否清楚：整机/模组/配件/套装/服务分别是什么。
- 起步人群是否清楚：如果目标用户超过 2 类，是否已选 beachhead。
- 市场口径是否清楚：上位参考市场和目标 TAM/SAM/SOM 是否分开。
- 竞品证据是否足够：是否覆盖官网以外的价格、渠道、用户评价或明确缺口。
- 差异化是否可测试：是否有对比对象、测试条件、指标、阈值。
- 技术和商业评分是否和证据一致：没有团队/渠道/样机证据时，不要给高分。
- 合规是否具体：不要只写"需合规"，要拆成需要谁复核什么。
- 验证计划是否能做决策：必须包含继续/调整/暂停门槛。

如果这些信息缺失，不要强行写乐观结论；在执行摘要和证据清单里列为关键缺口。

如果某个问题没回答，要么补，要么在文件顶部"待补充"清单里说明原因。

## 写作边界

- **不写代码、不写技术架构、不写 API、不写数据库设计、不写 PRD 详细功能规格。**
- MVP 建议只写"验证什么 + 核心功能（一句话） + 排除范围 + 成功指标"，不写实现路径。
- 技术可行性只写"路径是否成熟 + 依赖什么 + 风险"，不写具体技术选型方案。
- 如果用户要求实现细节，告知本 skill 不处理，建议改用工程类 skill。

## 不假设不捏造不猜测（核心原则）

- 每个数字、客户名、价格、增长率、用户数必须有源（`用户输入` 或 `公开资料`）。
- 无源字段 → 停止该章节，让用户决定（联网查 / 提供 / 跳过 / 取消）。**禁止假设、禁止"待验证数字"、禁止 AI 推断**。
- 多个方案（定价、GTM、MVP 范围） → 让用户选，**不要 AI 推荐一个然后继续**。
- 用户决定项（目标人群、产品形态、商业模式、地区、阶段） → 向用户确认，不猜测。

## 避免

- 大段行业背景堆砌。
- 没有公式的市场规模数字。
- 把上位市场数字包装成目标 TAM。
- 只列竞品名称，不分析替代方案。
- 只看竞品官网，不看价格带、渠道反馈和评价痛点。
- 只写产品功能，不写用户需求和商业路径。
- 把差异化写成口号，没有可测指标。
- 只写乐观机会，不写不确定性。
- 把 MRD 写成 PRD（功能列表 + 用户故事 + 验收标准）。

## 语气

专业、直接、可执行。可以指出不值得做的理由，不要为了迎合想法而强行乐观。

## 与模板对齐

`assets/mrd-template.md` 是 16 节结构。本指南的 9 个问题对应到具体章节，不允许出现"模板里有但回答不上来"的章节。每节填不出来时：

- 是因为信息不足 → **让用户决定**（联网查 / 提供 / 跳过 / 取消）。用户选"跳过"才写"用户选择跳过，本章无产出"，并在 §16 列出。
- 是因为不适用 → 在该节写"本场景不适用"，并说明为什么。
- 不要留空白行。
- **不要假设、不要"待验证数字"、不要 AI 推断填表。**
