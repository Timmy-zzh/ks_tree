# 第 4 周：通信模式和拓扑

## 学习目标

理解主要 Socket 类型，能够根据业务需求选择通信模式。

## 理论内容

### REQ/REP

- 简单同步 RPC；
- 严格一问一答；
- 适合短请求；
- 不适合复杂异步并发。

### PUSH/PULL

- 任务分发；
- 流水线；
- 多个 PULL worker 的负载分配；
- 背压和慢 worker。

### PUB/SUB

- 广播；
- 主题过滤；
- 发布者不等待每个订阅者；
- 慢订阅者和订阅建立前消息可能丢失；
- 不适合直接作为可靠任务队列。

### DEALER/ROUTER

- 异步请求和响应；
- routing identity；
- 自定义路由；
- 工作池；
- 多个未完成请求；
- 代理和服务网关。

### XPUB/XSUB、PAIR

- 发布订阅代理；
- 一对一控制通道；
- 内部控制和管理消息。

## 实践任务

使用仓库中的示例：

- `service_pub.cpp` / `client_sub.cpp`；
- `service_push.cpp` / `client_pull.cpp`；
- `service_router.cpp` / `client_dealer.cpp`。

完成：

1. 多客户端 REQ/REP；
2. 多 worker PUSH/PULL；
3. PUB/SUB 主题过滤；
4. ROUTER/DEALER 多请求并发；
5. ROUTER/DEALER 前后端代理。

## 本周输出

- Socket 类型对比表；
- 业务需求到通信模式的选择表；
- 四种拓扑图；
- REP 与 ROUTER/DEALER 的适用边界总结。

## 本周验收

能够为以下需求选择模式并说明原因：

- 查询用户信息：REQ/REP；
- 多 worker 处理任务：PUSH/PULL 或 ROUTER/DEALER；
- 广播配置变化：PUB/SUB；
- 客户端独立路由：ROUTER/DEALER；
- 线程间控制：PAIR 或 `inproc://`。
