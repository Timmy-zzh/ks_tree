# 第 6 周学习资料：队列、高水位与背压

> 本资料配套计划：[第 6 周：队列、高水位、阻塞和背压](第06周-队列高水位与背压.md)。

## 1. 学习目标

理解消息从业务线程到对端之间经过的队列和缓冲，能够解释 HWM、阻塞、非阻塞、超时、`EAGAIN` 和关闭等待。

## 2. 消息流和背压

```text
生产者
  -> Socket 发送队列
  -> Pipe/Session 队列
  -> TCP 缓冲区
  -> 对端接收队列
  -> 消费者
```

生产者快、消费者慢时，消息会在中间排队。队列无限增长会造成内存压力，因此 ZeroMQ 提供高水位（HWM）和超时等控制手段。

## 3. 重要选项

| 选项 | 作用 | 学习重点 |
| --- | --- | --- |
| `ZMQ_SNDHWM` | 发送方向高水位 | 通常按消息数，不是字节数 |
| `ZMQ_RCVHWM` | 接收方向高水位 | 不是整个系统的全局容量 |
| `ZMQ_SNDTIMEO` | 阻塞发送超时 | 超时后可能返回 `EAGAIN` |
| `ZMQ_RCVTIMEO` | 阻塞接收超时 | 无消息时返回超时结果 |
| `ZMQ_DONTWAIT` | 非阻塞收发 | 失败时检查 `EAGAIN` |
| `ZMQ_LINGER` | 关闭时等待队列消息 | 影响退出时间和消息保留 |
| `ZMQ_MAXMSGSIZE` | 最大消息大小 | 拒绝过大消息 |
| `ZMQ_IMMEDIATE` | 未建立连接时是否排队 | 连接状态和发送语义相关 |

通常应在 `bind` 或 `connect` 前设置 Socket 选项：

```cpp
zmq::socket_t socket(ctx, ZMQ_PUSH);
socket.set(zmq::sockopt::sndhwm, 10);
socket.set(zmq::sockopt::sndtimeo, 100);
socket.bind("tcp://*:5555");
```

## 4. 阻塞与非阻塞

默认发送或接收可能阻塞：

```cpp
socket.send(message, zmq::send_flags::none);
socket.recv(message, zmq::recv_flags::none);
```

非阻塞发送：

```cpp
auto result = socket.send(message, zmq::send_flags::dontwait);
if (!result) {
    // 检查是否因为当前不能发送而返回 EAGAIN
}
```

`send()` 成功表示本地 ZeroMQ 接受了消息，不表示对端已经消费。`EAGAIN` 说明当前操作不能立即完成，应用应选择丢弃、重试、降速或返回过载错误。

## 5. 实验一：小 HWM 和慢消费者

参考：

实验步骤：

1. 创建 PUSH/PULL；
2. 设置很小的 `SNDHWM` 和 `RCVHWM`；
3. 让 PULL 延迟读取；
4. PUSH 快速发送带序号消息；
5. 分别使用阻塞、`dontwait` 和 `SNDTIMEO`；

HWM 不是严格的全局字节上限。消息大小不同、多个连接和底层缓冲都会影响实际表现。

## 6. 实验二：超时、关闭和超大消息

- 设置 `ZMQ_RCVTIMEO`，在没有消息时观察返回值；
- 设置 `ZMQ_SNDTIMEO`，让消费者不读取，观察发送是否在期限后返回；
- 分别设置 `ZMQ_LINGER=0` 和较大值，比较关闭时间和未发送消息数量；
- 设置 `ZMQ_MAXMSGSIZE`，发送超过限制的消息，记录对端行为。

不要把 `LINGER=0` 当成“可靠快速关闭”。它可能直接丢弃尚未发送的消息。

## 7. 不同模式的差异

PUB/SUB 在高水位和慢订阅者场景可能丢弃消息；PUSH/PULL 会通过可写状态和队列产生背压；REQ/REP 还受模式状态机限制；ROUTER/DEALER 可自行设计队列和失败策略。必须以实际模式、连接状态和选项共同判断，不能用一个 HWM 结论概括所有 Socket。

## 8. 生产者的处理策略

队列接近上限时，应用可以：

1. 阻塞等待；
2. 在有限时间内等待，超时返回过载；
3. 非阻塞失败后丢弃低优先级消息；
4. 降低生产速率；
5. 扩大消费者数量；
6. 将消息持久化到外部系统；
7. 使用业务级排队和限流。

HWM 只是保护机制，不是完整的流量控制方案。
