# 第 8 周：业务可靠性、超时、重试和幂等

## 学习目标

建立端到端可靠性模型，解决“响应丢失导致重复业务”的问题。

## 理论内容

- 请求超时；
- 有限重试；
- 指数退避和随机抖动；
- request ID；
- 响应 ID；
- ACK；
- 幂等操作；
- 去重表；
- 数据库唯一约束；
- 业务状态查询；
- 服务端执行成功但响应丢失；
- 至少一次与 exactly-once 的区别。

## 关键故障场景

```text
客户端发送请求
  -> 服务端收到
  -> 服务端完成数据库更新
  -> 服务端发送响应前进程崩溃
  -> 客户端超时
  -> 客户端重试
  -> 服务端再次收到相同业务请求
```

## 实践任务

1. 为请求增加 `request_id`；
2. 服务端保存已处理请求；
3. 重复请求返回历史结果；
4. 使用数据库唯一约束或业务幂等键；
5. 设置有限次数重试；
6. 实现状态查询接口；
7. 在响应发送前故意终止服务端；
8. 验证业务不会重复执行。

## 本周输出

- 可靠性等级定义；
- 重试状态机；
- 幂等和去重方案；
- 失败场景和恢复策略表。

## 本周验收

必须能够准确说出：

```text
ZeroMQ 可以帮助传输消息，
但不会自动替业务实现 ACK、事务、幂等和 exactly-once。
```
