# 第 9 周学习资料：安全、认证与访问控制

> 本资料配套计划：[第 9 周：安全、认证和访问控制](第09周-安全认证与访问控制.md)。

## 1. 学习目标

本周将明文 TCP 示例提升到安全通信模型，理解加密、身份认证、授权、网络暴露和日志保护之间的关系。完成后能够：

- 识别默认 NULL security 的风险；
- 解释 CURVE、ZAP、服务端密钥和客户端密钥的关系；
- 使用错误密钥复现握手或认证失败；
- 评估 `tcp://*:5555` 的网络暴露范围；
- 制定密钥文件、消息大小、速率和日志的安全检查表。

## 2. 默认安全模型和威胁

普通 TCP 示例：

```cpp
sock.bind("tcp://*:5555");
```

通常使用 NULL security，意味着：

- 网络上的内容可能被窃听；
- 对端身份没有密码学保证；
- 任意能够访问端口的客户端都可能尝试连接；
- 日志可能泄露请求中的敏感数据；
- 监听 `*` 会暴露所有网卡，扩大攻击面。

安全分析应先问：谁能访问端口？是否需要加密？如何确认客户端身份？未授权客户端应该得到什么结果？密钥如何保存和轮换？

## 3. CURVE 和 ZAP

### CURVE

CURVE 基于 CurveZMQ 机制提供加密和身份认证。常见角色包括：

- 服务端长期公钥和私钥；
- 客户端公钥和私钥；
- 客户端保存并校验服务端公钥；
- 服务端通过白名单或 ZAP 判断客户端是否授权。

CURVE 解决传输加密和密码学身份，不会自动解决业务权限。例如“已认证客户端是否能调用删除接口”仍由应用层授权完成。

### ZAP

ZAP 是 ZeroMQ Authentication Protocol。可以使用它实现基于身份的访问控制。认证失败、未知身份和授权拒绝应记录结构化事件，但不要把私钥或敏感 payload 写入日志。

## 4. 配置思路

libzmq C API 常见配置项包括：

```text
ZMQ_CURVE_SERVER
ZMQ_CURVE_PUBLICKEY
ZMQ_CURVE_SECRETKEY
ZMQ_CURVE_SERVERKEY
```

cppzmq 版本应以当前 `zmq.hpp` 中的 `sockopt` 定义为准。配置顺序是：创建 Socket -> 设置安全选项 -> bind/connect -> 开始收发。

密钥文件建议：

- 只允许服务账号读取私钥；
- 公钥和私钥分开管理；
- 不提交到 Git；
- 不通过普通日志打印；
- 轮换时支持旧密钥和新密钥的过渡窗口；
- 启动时校验文件权限和格式。

## 6. 网络暴露检查

将：

```cpp
sock.bind("tcp://*:5555");
```

与仅监听本机或指定内网地址进行比较：

```cpp
sock.bind("tcp://127.0.0.1:5555");
```

生产检查项：

- 是否真的需要监听所有网卡；
- 防火墙是否只允许必要来源；
- 是否启用 CURVE 或其他安全层；
- 是否设置 `ZMQ_MAXMSGSIZE`；
- 是否限制连接速率和请求速率；
- 日志是否脱敏；
- 密钥是否有权限控制和轮换方案；
- 认证失败是否告警但不泄露密钥信息。

## 7. 常见误区

- 只加密不做授权；
- 把客户端公钥当作客户端业务用户 ID；
- 把密钥写进源代码或提交到仓库；
- 认为内网就不需要认证；
- 把认证失败的完整握手数据写进日志；
- 监听 `*` 后没有防火墙；
- 使用错误密钥实验时误判为网络故障。
